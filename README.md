# 衡評述值 Pricetory

AI 時代，大部分工作都被 AI 取代。體驗者來到 AI 經營的企業應徵，兩間 AI 企業的高層用月薪競標他。

- **A｜顧承淵**（營運長 COO）：節點 1，Boy 模型
- **B｜程以墨**（創新長 CIO）：節點 2，middle 模型

## Demo 網址

`six-branch` 沒有放在 GitHub Pages 上，可以用 githack 直接開（第一次會出現提醒頁，按「Open the page」）：

- 電腦一（主控，A 顧承淵）：`https://raw.githack.com/zoeytan-design/infection-echo/six-branch/index.html?host=1`
- 電腦二（B 程以墨）：`https://raw.githack.com/zoeytan-design/infection-echo/six-branch/index.html?host=0`

網址最後的 `?host=1`／`?host=0` 指定這台是不是主控電腦，不用再勾選。請用 Chrome 開，並允許鏡頭和麥克風。

## 開場前準備

1. 兩台電腦都用 Chrome 開啟網頁。
2. 電腦一選 **A 顧承淵**，並勾選「這台是主控電腦」。鏡頭、麥克風、鍵盤都接這台。
3. 電腦二選 **B 程以墨**，不要勾主控。
4. 兩台電腦各自從自己的喇叭念出自己角色的台詞。

只開一台電腦也能測試：另一個角色不在線時，主控電腦會代念他的台詞。

角色人設存在 Firebase。如果 Firebase 裡還是舊版資料，程式會自動改用內建的預設人設。要修改人設，請到「系統設定」編輯後按「發布」。

## 硬體（都接主控電腦）

- **RFID 讀卡機（RC522 + UNO）**：程式在 `arduino/pricetory_rfid/`。放卡送 `TAG:卡號`，拿起送 `TAG_OFF:卡號`。
- **敲槌按鈕（Nano）**：程式在 `arduino/pricetory_button/`。目前只有**一個**按鈕（D2），按下只送 `HIT`，分不出 A／B，所以成交暫時還是用鍵盤 A／B。之後若改成兩個按鈕、分別送 `HIT_A`／`HIT_B`，網頁就會直接成交，不用再改網頁。
- **第一次連接**：主控電腦開「系統設定」→ 按「🔌 連接 Arduino」→ 選讀卡機的 COM 埠（按鈕也一樣再選一次）。Chrome 會記住，之後重新整理或重新插 USB 都會自動連上。

## 主控電腦的鍵盤（硬體出問題時的備案）

| 按鍵 | 作用 |
|---|---|
| 1～5 | 放上職業卡（1 平面設計師、2 動畫師、3 網頁設計師、4 品牌策略與定位設計、5 遊戲設計師） |
| 0 | 拿起職業卡：面試立刻中止（成交或時間到之後拿起不影響收據） |
| A／B | 敲槌，與該企業成交 |
| T | 打字代替說話（麥克風有問題時的備案） |
| R | 重置 |
| D | 收音診斷面板（麥克風狀態、重啟次數、收到／略過的句子） |

## 流程

1. **放卡**：按 1～5（之後換成 RFID）。
2. **開始**：放了卡、鏡頭偵測到體驗者（面對鏡頭 1.5 秒）就自動開始，3 分鐘倒數開始（開場白包含在 3 分鐘內）。
3. **AI 開場**：顧承淵先開口：「歡迎你來應徵○○，請你介紹一下你自己並闡述你的應徵意願。」
4. **自我介紹 30 秒**：開場白說完才開始計時與收音。沒說話的話，第一輪不會開價。
5. **第一輪**：兩位都發言，要出價的先講，這一輪說話不會被處理。
6. **開放對話**（三人自由對話，價錢只會因為體驗者說的話而變動）：
   - 體驗者說話後，兩位依「想接話的程度」決定誰先回應，另一位有話才接。
   - 每次體驗者說話，每位最多調整出價一次。加價要有具體理由，新出價一定高於目前雙方最高價（至少多 1,000 元），每次最多比目前最高價多 40%。
   - 出價的那句只說金額、原因、期待，不問問題。
   - 體驗者開期待月薪時，AI 一定明確回應：接受、還價或拒絕。超過上限只能還價或拒絕。
   - 有人問體驗者問題就等 8 秒。沒回答時，由其中一位追問；連續兩次沒回答，兩位互聊一句再把話交回。
   - AI 之間最多連講兩句，第二句一定把話交給體驗者。
   - 爆料：體驗者說過話、雙方都開過價後隨機發生，一場最多兩次，第二次換另一方；被爆料者辯解後問體驗者相信誰。
7. **敲槌**：按 A／B。第一輪後才有效；該方還沒出價時無效，並由他說一句警語；有出價就以他目前的出價成交，兩位各說一句收尾。
8. **結束**：3 分鐘到自動結束（未成交）；任何時候拿起卡片（0）立刻中止。

## 收據

- 成交或時間到後（成交時兩位說完收尾的話；時間到沒人敲槌時由程以墨說一句收尾話），兩台螢幕都會蓋上一層黑色半透明，中間顯示放大的收據，左右各留 10% 黑邊，從頭慢慢捲到底。
- 收據顯示 1 分鐘後消失，整個遊戲自動重新開始。**中途拿走卡片＝無效，不會有收據。**
- 評選結果與最終月薪＝真實競標結果（有敲槌＝錄用、最終月薪＝成交價；沒敲槌＝不錄用、未成交）。
- 能力分數、雷達圖、「你說」原話、能力關鍵字由 AI 依體驗者說過的話評分，只當參考。只保留體驗者真的說過的原話。
- 加價明細＝（分數 − 3）× NT$1,000 × 面向權重。面向權重＝這個職缺有多看重這一項（1＝標準，例如遊戲設計師的專業技能是 1.2）。
- QR Code 打開 `receipt.html?id=單號`，從 Firebase `receipts/單號` 讀取，顯示收據文字並可下載文字檔。

## 可調整的設定

都在 `index.html` 的主程式開頭：

| 設定 | 預設 | 說明 |
|---|---|---|
| `TOTAL_MS` | 180000 | 整場時間 |
| `INTRO_MS` | 30000 | 自我介紹時間（AI 開場白說完才開始計時；全部包含在 3 分鐘內） |
| `OPENING_SPEAKER` | 0 | 放卡後先開口的 AI（0＝顧承淵，1＝程以墨）；台詞在 `openingLine()` |
| `ASK_WINDOW_MS` | 8000 | 問了問題後等體驗者回答的時間 |
| `LISTEN_WINDOW_MS` | 1500 | AI 沒問問題時，每句之間的空檔 |
| `PRODS_BEFORE_BANTER` | 2 | 連續幾次沒回答後兩位互聊 |
| `EXPOSE_MAX`／`EXPOSE_CHANCE` | 2／0.35 | 爆料次數上限與每次機率 |
| `SALARY_CAP_RATIO` | 1.3 | 出價上限＝行情上限 × 1.3 |
| `MAX_RAISE_RATIO` | 1.4 | 每次加價上限（比目前最高價多 40%） |
| `FIRST_BID_POS` | 0.7 | 第一口價最高到行情的哪個位置 |
| `USER_SILENCE_MS` | 1500 | 體驗者停頓多久算說完 |
| `ECHO_TAIL_MS` | 2500 | AI 說完後幾秒內仍檢查是否收到 AI 自己的聲音 |
| `RECEIPT_SHOW_MS` | 60000 | 收據顯示多久後自動重新開始 |
| `RECEIPT_SCROLL_MS` | 42000 | 收據從頂端捲到底部花多久 |
| `RECEIPT_SIDE_MARGIN` | 0.10 | 收據左右黑邊（螢幕寬度的比例） |
| `DIM_WEIGHTS` | | 各職缺五個面向的權重 |
| `TTS_MODEL` | eleven_turbo_v2_5 | 語音模型 |
| `CARDS` | | 職缺、月薪範圍、RFID 卡號 |

## 硬體（之後再接）

- 已寫好的 RFID 程式（`pricetory_rfid.ino`，送出 `TAG:`、`TAG_OFF:`）和敲槌程式（`pricetory_button.ino`，送出 `HIT`）可直接接上。在主控電腦的「系統設定」按「連接 Arduino」，各選一次連接埠即可。
- 收到 `HIT` 時目前只會提示「請按 A 或 B」，因為還沒決定敲槌時怎麼選成交對象。
